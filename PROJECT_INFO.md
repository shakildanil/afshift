# Информация о проекте

## Описание

Автоматизированная система сбора и обновления статистики депозитов (af_ftd events) из AppsFlyer для приложений Фонбет в Google Sheets.

## Технический стек

- **Python 3.12+**
- **AppsFlyer Raw Data Export API v5** - для получения статистики
- **Google Sheets API v4** - для обновления данных в таблицах
- **pytest** - для тестирования
- **schedule** - для планирования задач

## Основные компоненты

### 1. AppsFlyer Client (`src/appsflyer_client.py`)
- Подключение к AppsFlyer Raw Data Export API
- Получение in-app events отчетов
- Парсинг CSV ответов
- Поддержка множественных приложений

**Ключевые методы:**
- `get_in_app_events_report()` - получение событий за период
- `get_monthly_report()` - получение за весь месяц
- `get_reports_for_all_apps()` - обработка всех приложений

### 2. Data Processor (`src/data_processor.py`)
- Фильтрация событий по времени (event_time - install_time < 30 дней)
- Группировка по Media Source и Campaign
- Подсчет депозитов
- Создание сводных отчетов

**Ключевые методы:**
- `filter_events()` - фильтрация валидных событий
- `group_by_source_and_campaign()` - группировка данных
- `process_app_data()` - полная обработка данных приложения

### 3. Google Sheets Updater (`src/google_sheets_updater.py`)
- OAuth 2.0 аутентификация
- Создание и обновление листов
- Форматирование данных
- Автоматическое управление листами

**Ключевые методы:**
- `authenticate()` - аутентификация в Google API
- `update_sheet()` - обновление данных в листе
- `format_processed_data_for_sheet()` - форматирование для таблицы

### 4. Scheduler (`src/scheduler.py`)
- Планирование ежедневных обновлений
- Настраиваемое время запуска
- Логирование операций
- Обработка ошибок

**Ключевые методы:**
- `run()` - запуск планировщика
- `run_once()` - однократное выполнение

### 5. Main (`src/main.py`)
- Оркестрация всех компонентов
- Логирование процесса
- Обработка ошибок
- CLI интерфейс

## Бизнес-логика

### Фильтрация событий

Депозиты считаются валидными, если:
```python
days_difference = event_time - install_time
valid = days_difference < 30 days
```

**Обоснование:** Нужно учитывать только "свежие" депозиты от недавно установивших приложение пользователей.

### Подсчет депозитов

```
Каждая строка в CSV отчете = 1 депозит
Группировка: (Media Source, Campaign) -> count(rows)
```

**Пример:**
```
mintegral_int + winter_campaign -> 15 депозитов
unity_int + spring_campaign -> 23 депозита
```

### Обновление данных

**Частота:** Каждый день в 10:00  
**Период:** С 1-го числа текущего месяца до вчерашнего дня  
**Действие:** Полная перезапись данных за месяц

**Почему перезапись?** 
- Данные могут обновляться с задержкой
- Необходимо учитывать все изменения за месяц
- Гарантия актуальности

## Производительность

### Оценка времени выполнения

- **Получение данных из AppsFlyer**: ~5-30 секунд (зависит от объема)
- **Обработка данных**: <1 секунда
- **Обновление Google Sheets**: ~2-5 секунд

**Общее время**: ~10-40 секунд на одно обновление

### Ограничения

- **AppsFlyer API**: Rate limit зависит от плана
- **Google Sheets API**: 
  - 100 запросов в 100 секунд на пользователя
  - 500 запросов в 100 секунд на проект

## Безопасность
